# الحزمة المشتركة الرسمية للفريق | TEAM SHARED PACKAGE (v1.0.0)
## نظام الحضور الجامعي الذكي (University Attendance System)

---

> [!IMPORTANT]
> **طبيعة الحزمة (Read-Only Shared Reference Rule)**
> 1. **نسخة مرجعية قراءة فقط (Read-Only Reference):** هذه الحزمة هي المصدر الموحد للوثائق، العقود، البروتوكولات، والقواعد لكافة أعضاء الفريق.
> 2. **يُمنع التعديل المباشر:** لا يحق لأي عضو فريق تعديل أي ملف داخل هذه الحزمة أو العمل المباشر فيها.
> 3. **إدارة العقود والوثائق:** أي تغيير على المعمارية، عقود الـ API، هيكل قاعدة البيانات، أو قواعد الأمان يتم حصرياً عبر **قائد المشروع (Project Lead)**.
> 4. **آلية العمل:** يستلم كل عضو هذه الحزمة المشتركة (`team_package/`) كمرجع + حزمة المهمة الخاصة به (`Task Package`).
> 5. **الدمج النهائي (Final Integration):** عملية دمج وإجابة المخرجات بـ Backend / Frontend تتم حصرياً بواسطة قائد المشروع عبر نماذج الـ Handoff الرسمية.

---

## 1. محتويات الحزمة (Package Contents)

```text
team_package/
├── README.md                          # دليل الحزمة الشامل وقواعد الاستخدام
├── TEAM_START_HERE.md                 # الدليل الإرشادي الإلزامي للبدء والترتيب الموحد للقراءة
├── VERSION.md                         # وثيقة الإصدارات وحالة النظام وحالات البناء والاختبار
├── docs/                              # الوثائق الرسمية والدستور وقواعد الكود والمعمارية
├── api_contract/                      # عقود الـ API الرسمية والنماذج والاستجابات
├── database/                          # قاموس ومخططات قاعدة البيانات الرسمية (DDL & Schema)
├── shared/                            # الثوابت والنماذج المشتركة المعتمدة
├── local_protocol/                    # بروتوكولات الخادم المحلي، الـ QR، البصمة، والمزامنة
├── security/                          # وثائق وساسيات التشفير والأمان وتوثيق الأجهزة
├── integration/                       # قوالب تسليم واستلام المهام (HANDOFF_TEMPLATE.md)
└── prompts/                           # التوجيهات البرمجية المعتمدة لذكاء Antigravity الأصطناعي
    └── shared/TEAM_AI_BASE_PROMPT.md  # التوجيه الأساسي الموحد لذكاء المطورين
```

---

## 2. قواعد التزام الفريق (Team Commitment Rules)

1. **الالتزام بالعقود الرسمية:** يُمنع إضافة أي Endpoint، التعديل على أسماء الأعمدة بـ DDL، أو تغيير أسماء الأدوار والحالات دون إذن صريح.
2. **الترتيب الإلزامي لقراءة الوثائق:** يجب على كل عضو جديد قراءة الوثائق بالترتيب المكتوب بـ `TEAM_START_HERE.md` قبل تنفيذ أي كود.
3. **بيئة التطوير والتسليم:** يتم التطوير في حزم المهام المخصصة، وتسليم المخرجات عبر تقرير التسليم الرسمي بملف `HANDOFF_TEMPLATE.md`.
