# نظام التصميم وواجهة المستخدم الموحد | UI_UX_SYSTEM.md
## نظام الحضور الجامعي الذكي (University Attendance System)

---

> [!IMPORTANT]
> **المرجع الإلزامي للتصميم وواجهات المستخدم (Mandatory UI/UX System Rule)**
> يجب على كل عضو مسؤول عن واجهات المستخدم (Flutter Mobile & Flutter Web) الالتزام الصارم بهذا النظام لضمان توحيد الهوية البصرية، دعم اللغة العربية بالكامل (RTL)، وتحقيق معايير الجمالية العالية والاحترافية.

---

## 1. المبادئ العامة للتصميم (Core Design Principles)
- **لغة الواجهات:** Flutter UI مع دعم كامل للغة العربية والاتجاه من اليمين لليسار (`TextDirection.rtl`).
- **نظام التصميم الأساسي:** Material Design 3 (M3) مع سمات مخصصة تمنح مظهرًا حديثًا وفاخرًا (`Modern, Clean, Professional, Premium`).
- **التوافق والاستجابة (Responsive Layout):**
  - شاشات الهواتف (Mobile): دعم الهواتف بمختلف الأحجام مع التمرير السلس.
  - شاشات الويب (Web/Desktop): تخطيط متجاوب بشبكة (Grid System) وشريط جانبي قابل للطي ولوحات بيانات واسعة.
- **تأثيرات الزجاج (Glassmorphism):** يُسمح بتأثيرات الزجاج الشفاف الخفيف والمدروس (`BackdropFilter` خفيف) على البطاقات العائمة وشرائط التنقل. **يُمنع الإفراط في الـ Blur أو الـ Glow**.
- **تأثيرات التفاعل (Micro-Interactions):** تأثيرات انتقال ناعمة عند الضغط والتركيز. تأثير الـ Rainbow مسموح كتوهج/إطار خاطف وسريع عند الـ Press/Focus فقط، ويُمنع جعله لونًا دائمًا للواجهة.
- **الأيقونات والرموز (Icons Policy):**
  - **يُمنع منعًا باتًا استخدام الـ Emoji كأيقونات في الواجهات.**
  - الاعتماد الحصري على حزم الأيقونات الموجهة الرسمية (`Icons` من Material Icons أو FontAwesome) أو Vector Icons مرسومة كوديًا.

## 3. مقاييس المسافات ونصف القطر (Spacing & Radius Tokens)

### المسافات (Spacing):
- `spacingXS`: `4.0 dp`
- `spacingSM`: `8.0 dp`
- `spacingMD`: `16.0 dp` (المسافة القياسية للحشو الداخلي)
- `spacingLG`: `24.0 dp`
- `spacingXL`: `32.0 dp`

### نصف قطر الانحناء (Border Radius):
- `radiusSM`: `8.0 dp` (لحقول الإدخال والشارات)
- `radiusMD`: `12.0 dp` (للبطاقات والأزرار)
- `radiusLG`: `16.0 dp` (للحوارات والبطاقات العائمة)
- `radiusXL`: `24.0 dp` (للقوائم السفلية Bottom Sheets)

## 4. الحالات الإلزامية لكل شاشة (Mandatory Screen States)

يجب أن توفر كل شاشة تعرض بيانات ديناميكية الحالات الخمس التالية بوضوح:

1. **حالة التحميل (Loading State):** مؤشر تحميل دائري أو Shimmer Skeleton متناسق مع الحجم.
2. **حالة الفراغ (Empty State):** أيقونة توضيحية موجهة مع نص عربي واضح يشرح خلو البيانات وإجراء مقترح.
3. **حالة الخطأ (Error State):** إشعار بلون التنبيه يوضح المشكلة دون إظهار أخطاء تقنية غامضة.
4. **حالة إعادة المحاولة (Retry State):** زر واضح وسهل النقر (`إعادة المحاولة`) لإعادة طلب البيانات.
5. **حالة النجاح (Success State):** عرض سلس للبيانات مع تأثيرات دخول ناعمة.

## 5. مكونات الواجهة الموحدة (UI Component Specifications)

- **البطاقات (Cards):** استخدام خلفية `surface`، زوايا `radiusMD`، وحافة ناعمة `border`، مع ظل خفيف (`elevation: 1` إلى `2`).
- **الأزرار (Buttons):** أزرار عريضة وواضحة (`height: 48dp`) بنص واضح مع مؤشر تحميل مدمج عند إرسال الطلب.
- **حقول الإدخال (Inputs):** تدعم النص العربي ومحاذاة اليمين مع نصوص مساعدة ورسائل تحقق صريحة.
- **الجداول (DataTables في الويب):** رؤوس أعمدة واضحة، تقسيم صفحات (Pagination)، وخيارات تصفية وبحث سريعة.
- **القوائم السفلية والحوارات (Dialogs & BottomSheets):** زوايا مستديرة `radiusXL` ومظهر نظيف.
