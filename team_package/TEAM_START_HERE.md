## 2. النظرة العامة والمعمارية الشاملة (Project Overview & Architecture)

1. **اسم المشروع (Project Name):** نظام الحضور الجامعي الذكي (`University Attendance System`).
2. **الهدف العام (Overall Goal):** تسجيل وأتمتة الحضور والغياب الأكاديمي محلياً في القاعات ومركزياً بالجامعة بدقة وأمان عاليين دون الحاجة لاتصال بالإنترنت أثناء المحاضرة.
3. **المعمارية العامة (Architecture):** نظام هجين مدمج بين خادم مركزي (`NestJS/PostgreSQL`) وتطبيقات هاتف (`Flutter Mobile`) وتطبيق ويب إداري (`Flutter Web`) وخادم محلي مؤقت على هاتف المندوب (`LocalServer`).
4. **تطبيق الهاتف (`Flutter Mobile`):** واجهة الطالب والمندوب والأستاذ العملي والنظري.
5. **لوحة الويب (`Flutter Web / Admin Web`):** لوحة التحكم الشاملة لإدارة العمادة والنظام.
6. **الخادم المركزي (`NestJS Backend`):** خادم REST API المركزي المعتمد على NestJS.
7. **ORM قاعدة البيانات (`Prisma`):** المحرك الحصري لإدارة وصول قاعدة البيانات المركزية.
8. **قاعدة البيانات المركزية (`PostgreSQL`):** مستودع البيانات المركزي ذو الـ DDL القياسي.
9. **التوثيق والنفاذ (`Authentication`):** نظام توثيق مبني على `JWT` (رموز `Access Token` لـ 15 دقيقة و `Refresh Token` لـ 7 أيام).
10. **إدارة الأجهزة (`Devices`):** توثيق وربط هاتف المستخدم بحسابه عبر رموز التفعيل والبصمات الرقمية.
11. **الهيكل الأكاديمي (`Academic Structure`):** إدارة الأقسام، السنوات، الفصول، المواد، الشعب، وتوزيع التسجيلات.
12. **الخادم المحلي (`LocalServer`):** خادم HTTP/WebSocket مؤقت يستضيفه هاتف المندوب لاستقبال طلبات الحضور محلياً.
13. **جلسات الاستجابة السريعة (`QR Session`):** بث رمز QR متغيرة مشفرة تتضمن `Nonce` وطابع زمني لمنع التزوير وإعادة التمرير.
14. **التحقق الحيوي (`Biometric Verification`):** مطابقة بصمة/وجه الطالب محلياً قبل تشفير ورفع طلب الحضور.
15. **المزامنة non-realtime (`Synchronization`):** رفع دفعة الحضور `SyncBatch` محزومة وموقعة من هاتف المندوب إلى الخادم المركزي عقب إغلاق الجلسة.

## 3. الأدوار والحالات المعتمدة (Roles & States)

### 16. الأدوار الرسمية الـ 5 (Official System Roles):
- **`ADMIN`:** مسؤول النظام والعمادة.
- **`STUDENT`:** الطالب وتسجيل الحضور.
- **`DELEGATE`:** الطالب المندوب واستضافة الجلسة المحلية.
- **`PRACTICAL_TEACHER`:** الأستاذ المشرف على الشعب العملية.
- **`THEORETICAL_TEACHER`:** الأستاذ المشرف على المحاضرات النظرية.

### 17. الحالات الرسمية (Official System States):
- **حساب المستخدم (`AccountState`):** `PendingActivation`, `Active`, `Suspended`, `Deactivated`.
- **جهاز المستخدم (`DeviceState`):** `Unregistered`, `PendingVerification`, `Bound`, `Revoked`.
- **رمز التفعيل (`CodeState`):** `Generated`, `Sent`, `Used`, `Expired`, `Invalidated`.
- **الفصل الدراسي (`SemesterType`):** `FIRST`, `SECOND`, `SUMMER`.
- **نوع الشعبة (`SectionType`):** `PRACTICAL`, `THEORETICAL`.

## 4. سياسات الأمان والعقود والقواعد البرمجية (Security, Contracts & Rules)

18. **الأمان والتشفير (`Security`):** التشفير عبر `bcrypt` (12 rounds) للتمريرات، التوقيع المشفر لدفوعات المزامنة، وتطبيق سياسة منع Replay Attack.
19. **عقد الـ API (`API Contract`):** التزام تام بصيغ `API_SPECIFICATION.md` للمسارات والـ Payloads والبادئة `/api/v1/`.
20. **عقد قاعدة البيانات (`Database Contract`):** التزام كامل بـ DDL المسجل بـ `database_dictionary.md` وأسماء الأعمدة بـ `snake_case`.
21. **قواعد الكود (`Coding Rules`):** التزام تام بنظافة الكود وفصل الطبقات واستخدام DTOs والتسمية المعرفية الصارمة.
22. **قواعد استخدام الذكاء الاصطناعي (`AI Development Rules`):** استخدام Antigravity كمساعد زوجي والتوقف وعرض الخطة قبل التنفيذ.
23. **قواعد الدمج (`Integration Rules`):** عدم تعديل كود الأعضاء الآخرين وتجهيز تقرير التسليم بـ `HANDOFF_TEMPLATE.md`.

## 5. تعليمات العمل والملفات المحظورة وتصحيح التعارضات

### 24. الملفات المحظور تعديلها (Forbidden Files to Modify):
- لا تلمس ملفات المطورين الآخرين.
- لا تعدل عقود الـ API أو DDL أو وثائق المرجع بـ `team_package/`.
- لا تعدل إعدادات البيئة المركزية أو الحزم دون إذن قائد المشروع.

### 25. كيف تستخدم Antigravity (How to use Antigravity):
- قدم التوجيه الأساسي الموجود بـ `prompts/shared/TEAM_AI_BASE_PROMPT.md`.
- اطلب منه قراءة العقود المحددة قبل كتابة الكود.
- اشترط عليه عرض الخطة والتوقف قبل التعديل.

### 26. كيف تستلم المهمة (How to Receive Task):
- افتح حزمة المهمة المخصصة لك (`Task Package`).
- اقرأ نطاق المهمة بوضوح ومحددات المدخلات والمخرجات.

### 27. كيف تنفذ المهمة (How to Execute Task):
- صمم الحل في نطاق ملفاتك المحددة فقط.
- التزم بنمط المعمارية والقواعد البرمجية دون تغيير التقنيات.

### 28. كيف تختبر المهمة (How to Test Task):
- اكتب واقضِ اختبارات الوحدة (`Unit Tests`) الخاصة بمهمتك.
- تأكد من نجاح البناء `npm run build` أو `flutter build` وتمرير الاختبارات.

### 29. كيف تسلم المهمة (How to Submit Task):
- أنشئ تقرير التسليم الرسمي مستخدماً قالب `HANDOFF_TEMPLATE.md`.
- اذكر جميع الملفات المنشأة والمعدلة ونتائج البناء والاختبار.

### 30. ماذا تفعل عند وجود تعارض (Conflict Resolution):
- **توقف فوراً!** لا تحاول حل التناقضات بين العقود أو كود الأعضاء من تلقاء نفسك.
- ارجع فوراً إلى **قائد المشروع (Project Lead)** للبت في التعارض.
